# Adversarial review of clepsydra 0.2.0 (commit 18c33c4)

Reviewer stance: hostile referee (Bayesian phylogenetics, computational statistics, C).
Nothing in the repo was modified. All experiments ran on a copy in `/tmp/clrev/clepsydra`, and the synthetic data generator is `/tmp/clrev/exp/sim.py`. Every claim marked **[run]** was reproduced by running the binary. Every claim marked **[code]** was verified by reading the source at the cited line.

---

## 0. Executive summary

**The goal.** Take a cognate table for a small family with no calibrations (e.g. Arawan) and return well-calibrated node-age posteriors, estimating the tree if none is given.

**Verdict.** The tool cannot meet this goal today. It fails on the very scenario the owner is attempting, and it fails silently.

1. **There is no tree prior.** Any node age without a calibration gets a flat prior bounded by a hidden `1e15`-year ceiling (`gd_calibration.c:201`). On a synthetic 8-language tree:
   - With only extant tips calibrated, `date-tree` reports a root age of **8.8×10¹⁴ years**. The rate prior was centred exactly on the true rate, the true root is 4000 BP, R-hat is as high as 1.88, and no warning is printed **[run]**.
   - With a vague upper bound H on the root (true root 4000 BP), the posterior root mean is about **0.8·H**: 8 064 for H=10k, 16 422 for H=20k, 77 642 for H=100k **[run]**.
   - So the absolute age is set by an arbitrary bound, not by the data or the rate prior. This is the Arawan failure mode.
2. **Calibration priors are not what the user wrote.** The flat prior on the uncalibrated descendants multiplies each calibration density by a factor that grows like age^k. Every shipped example therefore has its root posterior **piled against the calibration ceiling**: Romance 2800, Polynesian 3100, Sino-Tibetan 9000, IE 9999. The `is_hard=0` ("soft") flag is ignored, so the ceilings are hard walls.
3. **Missing data is coded as agreement.** Cognate IDs of `.` are interned as a real class. Two languages that both lack a form for a concept are scored as cognate **[run]**: 60 missing concepts became 60 "matches".
4. **The tree is never estimated.** A Newick topology is mandatory, and topological uncertainty is ignored.
5. **Promised features are not wired in.** Reference concept and family priors, sensitivity presets, synonym marginalisation, loan/cognacy-confidence columns, WAIC/LOO, posterior predictive checks and T2 MCMC are all described as done. None is reachable from the engine or CLI. T2 cannot run in the sampler at all (`n_rates` is hard-wired to 1).
6. **The validation cannot see these failures.** The only tree SBC uses a quartet with a **fixed root**, which is exactly the regime where the missing tree prior and the step-size bug don't show. All examples use `uniform_node` calibrations only.

The C engineering is generally careful: overflow-checked allocations, iterative traversals, reproducible streams, checksummed checkpoints. The T1 recursion looks right and is brute-force-tested. The problems are in the statistical model, the defaults, and validation that does not test the regime the tool is meant for.

## 1. Critical findings

### C1. Uncalibrated node ages have an improper flat prior with a hidden 1e15 cap, and absolute ages are then set by that cap
**Code:**
- `src/gd_calibration.c:199-202` sets `node_lo=0`, `node_hi=1e15` for every node.
- `src/gd_mcmc.c:196-213`: `node_logprior` returns 0 for any node without a calibration.
- No Yule, birth–death or coalescent term exists anywhere (grep for `yule|birth` finds only prose).
- `docs/model-spec.md:648-649` promises "No hidden hard bounds beyond configuration".

**Mathematics.** With a strict clock and no node calibrations, the T1 likelihood depends on the ages only through r·t. Write the ages as T·(shape), with m free ages. The flat prior on the ordered cone contributes T^{m−1}, and the change of variable to log T contributes another T. If the data pin y = log(rT) at y₀, the posterior on x = log T is

  p(x) ∝ e^{m x} · N(y₀ − x; μ_r, s_r²) ⇒ x ~ N(y₀ − μ_r + m·s_r², s_r²).

The ages are inflated by a factor of e^{m s_r²}. With the defaults (s_r=0.8) and m=7 (8 tips) that is e^{4.5} ≈ 90×, before the cap or saturation intervene. The rate prior cannot hold this back: the ordered-cone volume term dominates. In addition, as T→∞ the contamination mixture makes the likelihood tend to a positive constant, ∏_c ε·CRP_c, so without the cap the posterior is **improper**. With the cap it is proper but dominated by the region near 10¹⁵.

**Evidence [run]** (8 tips, 200 concepts, T1 data simulated at r=1.5e-4, `--rate-logmean -8.8`, true root 4000):

| root constraint | posterior mean root | log-rate posterior |
|---|---|---|
| none (only `fixed_tip` 0) | 8.8×10¹⁴ (R-hat up to 1.88, ESS 6, acceptance 0.98) | −8.82 (= prior) |
| `hard_maximum` 10 000 | 8 064 | −9.43 |
| `hard_maximum` 20 000 | 16 422 | −10.15 |
| `hard_maximum` 100 000 | 77 642 | −11.69 |

The relative shape is roughly recovered; the absolute scale is the bound. A prior-only run on Romance (likelihood made constant) confirms that the induced priors are the uniform-order-statistics construction. For example, proto_romance's specified U(1400, 2050) has an effective prior mean of 1818 rather than 1725 **[run]**. Agent runs found the same pattern in IE (U[4000,10000] → prior median 8759) and Sino-Tibetan (U[4500,9000] → 8294).

**Fix (required before any uncalibrated use).**
- Add an explicit, proper tree prior on node ages with an explicit root prior:
  - a root-age prior (user-supplied, or a documented broad default such as a lognormal on log root age), and
  - a conditional density for the other nodes given the root that integrates to 1, so the root's marginal is the stated root prior.
- With all tips at 0, the simplest such construction divides the flat density by the ordered-region volume c·root^{m−1}, i.e. adds −(m−1)·log(root). This is the MCMCTree "uniform conditional" construction.
- Better options:
  - a birth–death prior with sampling fraction ρ and hyperpriors on λ and μ (Stadler 2010; Gernhard 2008), or
  - the calibrated-Yule correction for multiple calibrations (Heled & Drummond 2012). This fixes the calibration-marginal distortion (C2).
- With serially sampled tips such as Latin or Old Chinese, use the fossilised birth–death (FBD) / sampled-ancestor version.
- Remove the 1e15 sentinel. Where a node has no bound, make the bound infinite and let the tree prior keep the posterior proper.
- Add a `--prior-only` mode that writes the prior marginal for every node next to the posterior.

### C2. Calibration densities are distorted by the ordering constraint and the flat volume term, and `is_hard` is ignored
**Code:**
- `gd_calibration.c:215-218` and `:313-317`: `uniform_node` is always a hard box.
- `is_hard` is read at `gd_analysis.c:309-317` and never used again (grep).
- `docs/calibrations.md:93` says `is_hard=0` means soft.

**Failure.**
- **Committed examples:** every example root HPD ends exactly at its ceiling. The Romance root is 2669 with HPD 2518.7–2800.0, and proto_romance's HPD starts at 1400.0, the lower bound.
- **Widened windows:** proto_romance piles at 2050 instead.
- **Polynesian:** with a [500, 8000] window, Proto-Polynesian becomes 7096 BP.
- **Sino-Tibetan:** with [3000, 20000], the root becomes 16289 BP.

The reported dates are the calibration window combined with the t^k volume tilt.

**Fix:**
- Implement soft uniform bounds (e.g. a uniform with 2.5% exponential or normal tails, as in MCMCTree and BEAST).
- Use a tree prior with calibration-density conditioning (C1).
- Always publish the effective prior next to the posterior.
- Flag any HPD endpoint within 1% of a bound.

### C3. Missing cognate IDs (`.`) and the `status` column are treated as real data
**Code:**
- `gd_forms.c:106-158` (`row_cb`) never checks `gd_tsv_is_missing` on `cognate_id` and never reads `status`.
- `gd_analysis.c:920` counts `strcmp(".", ".")` as a match.
- `gd_analysis.c:526-545` interns "." as a cognate class in T1.

**Failure [run]:** for 100 concepts where 60 are `.` in both languages, `date-pair` reports "100 shared, 80 cognate". In T1, every language missing a concept is placed in one shared cognate set. Many CLDF exports leave unassigned forms empty or `.`.

**Effect:** dates become strongly too young, and silently.

**Fix:**
- Skip rows whose `cognate_id` is empty, `.` or `?`, or whose `status ∈ {missing, excluded, absent}`.
- Report the number of skipped rows.
- Add a regression test.

### C4. Extant tips silently become free parameters unless the user lists a `fixed_tip 0` for every one
**Code:**
- `gd_calibration.c:199-202`: tips get [0, 1e15].
- `gd_mcmc.c:281-283, 426-433`: any node with hi > lo is sampled.
- `docs/model-spec.md:45` says extant tips are at age 0.

**Failure [run]:** with only a root calibration, the extant tips A–H get posterior ages between 516 and 1297 BP. This shortens their branches and biases every internal age. No warning is printed. The Arawan user will almost certainly hit this.

**Fix:**
- Default tips to age 0.
- Require an explicit tip-age calibration (point or interval) for ancient tips.
- Error if a tip carries a non-fixed prior without opting in.

### C5. Age proposal steps start at ~10¹⁴ years, and warm-up cannot adapt them
**Code:**
- `gd_mcmc.c:431`: `step = age_step0_frac * (node_hi - node_lo)`, which is 0.1×1e15 for any node not below a bounded ancestor.
- `gd_mcmc.c:475-483`: the Robbins–Monro gain γ_n = (n+10)^{-0.6} allows a total log-step reduction of only ≈0.44·Σγ_n ≈ 20 in 2000 warm-up iterations, a factor of about 10⁻⁹. The step therefore stays around 10⁵ years.
- `gd_calibration.c:222-231` computes `hi = exp(mean + 5·sd)` for **`normal_node`**, treating the mean as a log-mean. That is `exp(4000+…) = inf`, so a normal root calibration never bounds anything.

**Failure [run]:** 8-tip synthetic tree, root `normal_node(4000, 200)`, defaults:
- every age has acceptance **0.005**;
- ESS is 12–60;
- R-hat reaches **1.27**;
- the CLI prints no warning.

**Fix:**
- Initialise age steps from the current age scale (e.g. 0.1·(parent − max child) at the initial state), or propose on a log or ratio scale (node-height proportions with the correct Jacobian).
- Use dual-averaging or variance-based adaptation with a larger initial gain.
- Correct the `normal_node` bound to `mean + 10·sd`.
- Warn, and exit non-zero unless `--allow-unconverged` is given, when R-hat > 1.01, bulk/tail ESS < 400, or any acceptance rate is < 0.05 or > 0.95.

### C6. No tree estimation, and topological uncertainty is ignored
**Code:**
- `gd_analysis.c:464-467`: "no Newick tree supplied" is an error.
- There are no topology moves, and no way to integrate over a set of trees.

**Effect:** the owner's goal explicitly includes "estimate the tree if not given". For Arawan the internal structure is debated (e.g. the Madi cluster vs Paumarí vs Dení–Kulina). Conditioning on one topology understates every node-age interval, and a node that is not monophyletic in the posterior should not have a reported age at all.

**Fix (in order of effort):**
1. Accept a posterior tree sample from an external tool (e.g. a BEAST2 or MrBayes binary-cognate run). Date each tree, or a thinned subset, and pool the results. Report node ages only for clades with posterior support, conditional on monophyly.
2. For n ≤ 8 tips (at most 135 135 rooted binary topologies), estimate a marginal likelihood per topology (stepping-stone) for the top-K topologies and average over them.
3. Implement proper topology MCMC (narrow and wide exchange, subtree slide, Wilson–Balding) with the tree prior from C1. Without C1 this is not even well-defined, because the flat improper age prior gives every topology an infinite or arbitrary volume.

## 2. Major findings

### M1. Without calibrations, the only source of absolute time is a fixed "Swadesh" rate prior; no external data informs it
- **Defaults:** `gd_analysis.c:368-369` uses log-rate N(−8.80, 0.80) per year (0.86 retention per kyr per lineage, Swadesh-100). `docs/priors.md` itself calls this a "legacy fallback anchor, not an empirical conclusion".
- **Unused reference priors:** the C engine never reads `concept_priors.tsv` or `family_priors.tsv`; grep finds no loader, and `reference_mode` does not exist. The reference builder emits synthetic numbers stamped with real-looking source keys (`tools/reference_builder/synthetic_sources.py:146-156`). Pagel 2007, Vejdemo–Hörberg and ASJP are stubs.
- **Rate model:** the T1 rate is one per-year replacement rate shared by every concept, list and coding scheme. It is not adjusted for list composition (IE-CoR 170 concepts ≠ Swadesh-100 ≠ Leipzig–Jakarta), cognate-coding granularity (lumpers vs splitters), or loan handling. All of these move the effective rate by factors comparable to the prior SD.
- **Fix:**
  - Build the rate prior empirically from **this model fitted to calibrated families**. Fit T1 (with concept heterogeneity) to N ≥ 10 well-calibrated families coded the same way (Lexibank/IE-CoR-style), and fit a hierarchical model log r_f ~ N(μ, τ²).
  - Use the **posterior predictive for a new family** (μ̂, sqrt(τ̂² + se²)) as the uncalibrated-family prior.
  - Validate it with leave-one-family-out coverage of known node ages (§4).
  - Store list composition and coding-protocol metadata with the prior, and refuse or warn on mismatched lists.

### M2. Among-concept rate heterogeneity is off in the CLI, and concept rates are never externally informed
- `cfg->sample_concept_rates` defaults to false (`gd_mcmc.c:140`), and `gd_analysis.c:659-672` never sets it. No CLI flag exists.
- When it is on, the deviations are N(0, 0.5) with no reference mean (`gd_mcmc.c:249`), and the 0.5 is unfounded. Pagel et al. 2007 report roughly a 100-fold rate range, i.e. a log-SD above 1.
- A homogeneous-rate fit to heterogeneous data is the classic cause of glottochronology underestimating deep nodes, because saturation is mis-modelled.
- **Fix:**
  - Default to a gamma or lognormal among-concept rate variation whose SD has a hyperprior.
  - Optionally use external relative rates as a prior mean, with the depth correction in M14.
  - Integrate the per-concept rate out by quadrature, as P1 already does, instead of sampling 200 extra MH parameters.

### M3. The contamination weight ε is fixed at 0.05 in `date-tree`, and is 0 in `date-pair`
- `gd_analysis.c:668` sets `fixed_epsilon` and never sets `sample_contamination`. `gd_analysis.c:939-942` passes `eps = 0` to P1, and `gd_pairwise_p1.c:176` ignores `eps_a`/`eps_b`.
- With ε fixed, the noise component's age-independent likelihood floor is what makes the C1 posterior improper.
- **Fix:**
  - Sample ε ~ Beta(1, 19); the code already exists.
  - Report per-concept P(contaminated), which is computed (`gd_model_novel_state.c:668`) and then thrown away.
  - Give P1 a real ε with a sensible chance-match probability. The hard-coded `q_c = 0.5` at `gd_pairwise_p1.c:254` means two unrelated words match half the time, which is absurd for cognacy. Use q ≈ 1/(number of classes) or estimate it.

### M4. Borrowing that produces a *compatible* pattern is invisible, and `loan_probability` is ignored
- In T1, a borrowing between sister languages creates a shared class that extends cleanly over the tree. The model reads it as retention, and dates get younger.
- The contamination mixture only catches non-extendable patterns. The loan-robustness test (`tests/simulation/test_mcmc_relaxed.c`) injects only incompatible patterns.
- For Arawan, with intense contact among Purus-basin languages and with Arawakan/Panoan neighbours, this is the main bias.
- **Fix:**
  - Use `loan_probability` and `inheritance_probability` as per-cell mixture weights between "inherited" and "missing/independent".
  - Offer a `--loans exclude` mode.
  - Add a simulation test with compatible loans between sister tips.

### M5. Synonyms are resolved by argmax weight, with file order breaking ties, and cognacy confidence is ignored
- `gd_forms.c:243-258` implements this, and `tests/unit/test_forms.c` enshrines it.
- `docs/model-spec.md:178-181, 443-454` promise exact pairwise marginalisation and latent-primary MCMC blocks; neither exists.
- `cognacy_confidence`, `inheritance_probability`, `loan_probability`, `status` and `analysis_id` are never read (`gd_forms.c:92-95`). Several `analysis_id` codings in one file are merged by max weight.
- **Effect:** results depend on row order. Picking a non-cognate synonym inflates distances.
- **Fix:** marginalise over synonyms in T1. A concept's observation is a set of classes per tip; the simplest correct approach is a likelihood over the choice of primary, or the Rönchen et al. synonym extension. At minimum, randomise the primary per replicate and report the spread.

### M6. T2 (binary gain/loss) is dead code in the sampler, and its partition weights are never applied
- `gd_mcmc.c:160` always sets `st->n_rates = 1`, while `t2_model_loglik` requires `n_rates >= 2` (`gd_model_binary.c:426-429`). Any MCMC run errors.
- The only test hand-builds a state with `n_rates = 2` (`tests/likelihood/test_t2_likelihood.c:815`).
- `gd_t2_partition_weights` is computed but `gd_t2_loglik_dataset` sums unweighted (`gd_model_binary.c:322`). The docs claim meaning-weighting by default.
- T2 is not reachable from the CLI, yet README:8-9 presents it as implemented.
- **Fix:** either wire it up (two rate parameters, weights applied as tempering per meaning, cross-checked against BEAST2 or RevBayes on a shared tree), or label it experimental.

### M7. The `date-pair` uncertainty knob does not do what it says
- `--rate-logsd` is described as the "prior sd of the log rate". It is actually the **per-concept** log-rate SD, integrated independently per concept (`gd_analysis.c:922-923`, `gd_pairwise_p1.c:126-157`), and it averages out over 170 concepts.
- The only clock-level uncertainty is β with SD hard-coded at 0.3 (`gd_analysis.c:941`).

| `--rate-logsd` | median | 90% interval |
|---|---|---|
| 0.1 | 1214 | 702–2113 |
| 0.6 | 1088 | 624–1905 |
| 1.5 | 718 | 392–1308 |

**[run]**, Italian–Spanish. A larger "uncertainty" gives a *younger, not wider* answer, because the lognormal mean rate grows with the SD at a fixed median.
- The sensitivity presets are hard-coded to STANDARD, and even they don't scale β (`gd_pairwise_p1.c:231 vs 251`).
- **Fix:** expose the β SD as the clock-uncertainty parameter; parameterise per-concept heterogeneity by its mean rather than its median, or document it; expose the presets.

### M8. Decay-law posteriors treat the published constants as exact
- `gd_decay.c:19-30, 98-178`: Swadesh r=0.86, Starostin λ=0.05, Vasilyev f=0.08 and λ=0.45 are fixed constants.
- The posterior width therefore reflects only binomial noise, and absolute dates are overconfident by construction.
- **Inconsistent time factors:** Swadesh uses `r^{2t}` (per lineage), while the two-component "regular" part uses `r^{t}` (per pair) (`gd_decay.c:41, 57`).
- **Contradictory rationale:** `docs/decay-laws.md:19` says retained words become "increasingly stable, so replacement accelerates".
- **Fix:** put priors on the law constants and document the time convention per law.

### M9. The pairwise P1 model assumes contemporaneous sisters
- An ancestor–descendant pair (Middle Korean vs Gyeonggi in `examples/families_pairwise/output/koreanic`) gets a divergence of 230 BP. That is below the ancestor's own attestation (~550 BP).
- Tip ages a1 and a2 exist in the library, but the CLI always passes 0, 0.
- `absolute_anchored = (a1>0 || a2>0)` (`gd_pairwise_p1.c:330`) is conceptually wrong: one dated tip doesn't break the r·d confounding.
- **Fix:** expose tip ages, and reject or flag pairs where one member is a documented ancestor.

### M10. Diagnostics are incomplete and never acted on
- `gd_diagnostics.c` implements rank-normalised split R-hat, but not the folded/tail R-hat. The Vehtari et al. 2021 recommendation is the maximum of the two.
- Bulk-ESS only: no tail-ESS, although 90% HPD endpoints are the headline output.
- The Geyer initial-positive-sequence pairs start at (ρ₁, ρ₂) rather than (ρ₀, ρ₁) (`gd_diagnostics.c:244-251`). This differs from Stan/posterior and loses the reversibility-based guarantee. Minor numerically; easy to align.
- No MCSE.
- The CLI prints no warnings at all (grep `cli/commands.c`), even at R-hat 1.88 and ESS 5–6 **[run]**.
- The LOCO tool prints R-hat with `%.1f` (`tools/validation/calibration_benchmark.py:216`), so 1.04 shows as "1.0".
- **Fix:** add tail-ESS, folded R-hat and MCSE; fail loudly; print R-hat to 3 decimals.

### M11. Single-site random-walk MH with full likelihood recomputation every move
- Every age, rate or branch move recomputes all concepts, including the data-extension step, which is independent of the parameters (`gd_model_novel_state.c:617-618, 786-808`).
- The extension, the sorted keys and the CRP noise term could be computed once per concept.
- Proposals that cross a parent or child bound are rejected rather than reflected.
- With a relaxed clock that is about 2n + 1 full likelihood evaluations per sweep, which is why ESS is low (IE: ESS 167 from 24 k draws).
- **Fix:**
  - Cache the extension and noise term.
  - Do partial-likelihood updates: only the path to the root changes.
  - Use a node-slide on the ratio (t − max child)/(parent − max child) with a Jacobian, plus subtree rescaling and rate–age compensating moves (scale r up and every age down, a "clock-preserving" move that kills the main r–t ridge).
  - Consider HMC/NUTS on transformed node heights; T1 is differentiable in the ages.

### M12. Relaxed clock: uncorrelated lognormal multipliers with no identifiability safeguards; validation measures coverage, not calibration
- Prior: log m_b ~ N(−σ²/2, σ²), σ ~ HalfNormal(0.3) (`gd_mcmc.c:216-224`). That is reasonable, but without calibrations, or with only one, branch rates and durations are non-identifiable. The confounding diagnostic only reports this after the fact.
- **LOCO benchmark:** the relaxed clock reaches 8/9 coverage with HPDs whose lower ends are near 0 (Greek 0.1–3025, Burmese 0.4–1049), while point errors stay at ±1100–2700 years.
- **Weak tests:**
  - The σ_b shrinkage test (`test_mcmc_relaxed.c:293`, `mean_sigma < 0.30`) cannot fail under a HalfNormal(0.30) prior, whose mean is 0.24.
  - "Relaxed does not beat strict" is tested as `lppd_relaxed <= lppd_strict + 1.0`.
- **Fix:** score LOCO with the interval score or CRPS and a prior-only baseline; compare σ_b against the prior-only posterior.

### M13. `--cal-widen` corrupts `offset_lognormal_node`
- `gd_analysis.c:240-244` multiplies `p2` (the log-mean for this type) instead of `p3` (the log-SD).
- With f=2, the root median jumps from 1606 to 39 915 BP (agent run).
- Soft min/max calibrations are never widened.
- **Fix:** widen per type, and add a test for each type.

### M14. The tools' concept-stability priors are statistically unsound, and the engine doesn't read them anyway
- `tools/analysis/concept_stability.py`:
  - **Fixed SD** of 0.5 (`:153`), ignoring binomial noise with 3–8 pairs per concept.
  - **Clamping** s to [0.01, 0.99] (`:143`); 497 of 767 pooled concepts sit at s=0 or s=1.
  - **Depth confounding** from pooling raw similarities across families (405/767 concepts come from a single family).
  - **Dependence:** the O(N²) pairs are counted as independent.
  - **Loans:** counted as agreement.
- The leave-family-out coverage study simulates exactly the model it fits, and still under-covers: 0.82 at nominal 0.90 with method-of-moments τ̂ truncated at 0.
- **Fix:**
  - Estimate log(−log s_fc) = log r_c + log d_f + noise jointly (two-way random effects).
  - Better still, fit T1 per family with concept random effects and pool the concept effects hierarchically.

## 4. What a hostile referee would demand before trusting any date

1. **Prior-vs-posterior tables for every node.** Use likelihood-off MCMC on the exact configuration, and show the KL divergence or SD ratio. Today the Polynesian root posterior (2908, HPD 2675–3100) equals its prior-only run (2910, 2681–3100).
2. **Simulation-based calibration through the full CLI pipeline** in the regimes users actually run:
   - (a) uncalibrated root with the rate prior only;
   - (b) one normal or lognormal root calibration;
   - (c) ancient tips;
   - (d) relaxed clock;
   - (e) concept heterogeneity;
   - (f) contamination and *compatible* loans;
   - (g) missing data and synonyms.

   Report per-parameter rank histograms or ECDF difference plots. Today only P1's T and a fixed-root quartet are tested.
3. **Misspecification simulations.** Fit with T1 to data simulated with rate heterogeneity among concepts and lineages, borrowing, coding noise and time-dependent rates, and report bias and coverage of the node ages. Glottochronology's known failures (Bergsland & Vogt 1962) must be shown to be absent.
4. **Out-of-sample validation of the uncalibrated mode on real families.** Take N ≥ 10 families with independent historical or archaeological node dates (Romance, Germanic, Slavic, Turkic, Polynesian, Bantu sub-branches, Mayan, Semitic, …). Date each with **no** calibrations, using the rate prior learned from the other families. Report coverage and the interval score per node. This is the experiment that justifies running the tool on Arawan.
5. **Agreement with established tools** on shared data and identical models: BEAST2 (binary covarion/CTMC with ascertainment, birth–death tree prior), RevBayes, and Rönchen et al.'s own T1 code. Show identical likelihoods at fixed parameters and near-identical posteriors.
6. **Topology uncertainty:** clade support, and dates reported conditional on monophyly.
7. **Robustness:** to cognate-coding (lumper/splitter variants, alternative `analysis_id` codings), to the concept list (Swadesh-100 vs 200 vs Leipzig–Jakarta), to the treatment of loans, and to the tree prior (Yule vs birth–death vs uniform-conditional).
8. **Plausible example outputs, or an honest explanation.** Today Romance internal nodes are far too young: Spanish–Portuguese 379 BP, Gallo-Iberian 663 BP, although French is attested as distinct by 842 CE. Polynesian Central-Eastern comes out at 1752 BP against settlement around 1000–700 BP. Sino-Tibetan subgroup ages copy their tip calibrations.

## 5. Can Arawan get honest absolute ages at all?

Only through an externally learned rate prior, and the uncertainty is necessarily wide.

- With no calibrations, the posterior age scale equals the posterior of (data-determined r·t) divided by the rate prior. The interval can be no narrower than the cross-family dispersion of the rate in this model under this coding protocol, plus estimation error.
- Realistically, that dispersion is a log-SD of about 0.4–0.7 at best, which gives a 90% factor of roughly ×2–3 either way.
- An honest Arawan root date is therefore something like "1500–4500 BP", not ±300 years.
- What must not happen is what happens now: the scale silently set by a 1e15 cap or an arbitrary hard maximum.
- Archaeological or geographic soft maxima (e.g. on Proto-Arawan via Purus-basin settlement), and cross-family consistency with Arawakan contact loans, can tighten this, provided they enter as proper, soft, documented priors with a tree prior that does not distort them.

## 6. The 15 most impactful improvements, prioritised

1. **Add a proper tree prior with an explicit root-age prior and remove the 1e15 cap** (C1).
   - Start with uniform-conditional on the root (add −(m−1)·log root when all tips are at 0); move to birth–death or FBD with hyperpriors.
   - Without this, uncalibrated and loosely calibrated dates are meaningless.
2. **Fix the data-intake bugs that bias dates silently** (C3, C4):
   - drop missing or `status`-excluded cognate IDs;
   - default extant tips to age 0;
   - report skipped and missing counts in the manifest.
3. **Add a `--prior-only` mode and print each node's prior next to its posterior**, with a per-node "data informativeness" ratio and a warning when the HPD touches a bound.
4. **Fix the sampler's scale handling and gate on convergence** (C5, M10, M11):
   - state-relative or log/ratio age proposals and a clock-preserving r·t move;
   - correct the `normal_node` bound;
   - tail-ESS and folded R-hat;
   - hard warnings and a non-zero exit on non-convergence.
5. **Learn the clock-rate prior empirically from calibrated families under T1 itself** (hierarchical across families, coding protocol fixed). Ship it as a versioned TSV that the engine actually loads; delete the dead reference-builder synthetic sources (M1, M14).
6. **Leave-one-family-out validation of the *uncalibrated* mode on ≥10 real families**: coverage and interval score of node ages (§4.4). This is the publishable core claim.
7. **Tree estimation / topology uncertainty** (C6). First accept and integrate over an external posterior tree set; then add topology MCMC (exchange, subtree slide, Wilson–Balding) using the item-1 prior. For n ≤ 8, model-averaging over the top topologies by marginal likelihood is feasible.
8. **Among-concept rate heterogeneity on by default**, integrated out analytically per concept, with a hyperprior on its SD and optional external relative-rate means (M2).
9. **Turn on and report contamination properly**: sample ε, export per-concept P(contaminated), and use a sensible chance-match q in P1 (M3).
10. **Borrowing model**: use `loan_probability`/`inheritance_probability`, add an exclude-loans mode, and test with *compatible* simulated loans (M4). This is critical for Amazonian families.
11. **Synonym and coding uncertainty**: marginalise over synonyms in T1, use `cognacy_confidence`, and support several `analysis_id` codings as a sensitivity axis (M5).
12. **Soft calibrations done right**: honour `is_hard`, use soft uniform tails, condition calibration densities through the tree prior (Heled & Drummond), and fix `--cal-widen` for each type (C2, M13).
13. **Full-pipeline SBC suite** covering uncalibrated, normal-root, ancient-tip, relaxed, heterogeneity, ε and missing-data regimes, per parameter, run through `gd_analysis`, plus negative controls that are asserted to fail (m10, m11).
14. **Cross-validate against BEAST2/RevBayes and the Rönchen et al. reference code** on shared datasets. Then either finish T2 (wire two rates, apply partition weights, ascertainment checks) or remove it from the claims (M6).
15. **Make examples and docs honest**:
    - regenerate outputs with prior-only comparisons;
    - flag the too-young Romance and too-old Polynesian internal nodes;
    - score LOCO by interval score rather than coverage alone;
    - fix the claim/test mismatches (σ_b test that cannot fail, SBC counts, "Milestones complete", 190 vs 261 tests, `pair_context`), and the pairwise decay laws' fixed constants (M7, M8, M12).
