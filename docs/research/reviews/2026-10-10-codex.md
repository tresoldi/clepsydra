## Executive verdict

Clepsydra is not ready to support defensible calendar dates for an uncalibrated family such as Arawan, and it does not yet meet the stated ultimate goal. The strongest blocker is not merely weak information: the shipped tree analysis has no declared generative prior on the root or uncalibrated node ages. It instead uses constant density on the chronology polytope cut off at an undocumented $10^{15}$-year ceiling. With the default contamination mixture, the likelihood retains a positive age-independent floor, so removing that ceiling would make the posterior improper. In a copied build, removing the Romance node calibration while keeping the eight tips fixed at zero produced a root median of about $9.4\times10^{14}$ BP, almost exactly the median induced by the artificial ceiling.

The second central problem is a gap between the documented model and the executable product. The CLI uses a fixed topology, one global T1 rate, a fixed contamination weight, deterministic winner-take-all synonym handling, and hard-coded rate priors. It does not load the documented concept/family prior packages, does not perform T2 inference, and ignores cognacy confidence, borrowing probabilities, status, and alternative analyses. Several of these richer components exist as lower-level routines or tests, but they are not the analysis users run.

I would treat every present calendar date without an external calibration as a clock-prior-conditioned scenario, not as a calibrated posterior age. The current defaults amount to a softened classical Swadesh clock whose transportability to Arawan has not been demonstrated. When neither a historical calibration nor a validated external clock package exists, the honest primary result is lexical time; calendar ages should be a sensitivity family indexed by explicit clock priors.

## Findings

### 1. Critical — the root and uncalibrated node-age prior is an undocumented ordered-flat measure with a hidden $10^{15}$-year bound

**Location:** `src/gd_calibration.c:198-202`; `src/gd_mcmc.c:196-213,232-236`; contradiction at `docs/inference.md:76-86` and omission at `docs/model-spec.md:63-68`.

**Failure scenario:** Every unconstrained node receives `[0, 1e15]`; an uncalibrated node contributes zero log density. The effective base prior is therefore

\[
p(\mathbf t) \propto \mathbf 1\{0\le t_v\le10^{15},\ t_{parent}>t_{child}\}
\]

times calibration factors. It is not a collection of independent Uniform priors. Descendant-volume effects make ancestral marginal priors increasingly favor old ages. With $m$ ordered free ages below a root $R$, the root marginal typically contains a factor proportional to $R^{m-1}$; therefore adding taxa or changing topology changes the effective clock/age prior. In the copied Romance run, seven free internal ages gave root median $9.44\times10^{14}$ BP; the ordered-flat prior predicts $10^{15}2^{-1/7}=9.06\times10^{14}$.

**Fix:** Specify and implement a proper time-tree prior: for example a proper root-age distribution plus normalized conditional node proportions, or a birth–death/coalescent-style prior conditional on the topology. State its full joint density and Jacobians. Remove the magic ceiling and add prior-predictive plots and tests showing invariance to numerical proposal limits. Refuse calendar-time runs without a proper root/time-tree prior.

### 2. Critical — with default contamination, the intended unbounded posterior is mathematically improper

**Location:** `src/gd_model_novel_state.c:517-531,665-669`; default fixed epsilon at `src/gd_analysis.c:368-370,598-600,665-669`.

**Failure scenario:** T1 uses $(1-\epsilon)L_{tree}+\epsilon L_{noise}$, and the CRP noise likelihood is positive for every observed partition. As all free ages go to infinity, each concept retains a positive $\epsilon L_{noise}$ floor independent of age. Combined with flat Lebesgue density on unbounded ages, the posterior integral diverges. The $10^{15}$ cap does not approximate a proper posterior; it creates one whose answer depends on the cap.

**Fix:** A proper root/time-tree prior is mandatory. Add a propriety check for hard-minimum-only, soft-minimum-only, or entirely unconstrained roots. Add regression tests that enlarge any numerical ceiling and verify unchanged posteriors. Treat a non-vanishing robust-likelihood floor explicitly in the propriety analysis.

### 3. Major — the routine called a prior sampler does not sample the MCMC target prior

**Location:** `src/gd_calibration.c:365-457`; target prior at `src/gd_mcmc.c:196-213`; prior-only requirement at `docs/calibrations.md:69-76`.

**Failure scenario:** `gd_cal_sample_prior` samples root-down, choosing each child uniformly below its already sampled parent. This introduces factors such as $1/(t_{parent}-lo)$, whereas the MCMC target is constant density over the ordering polytope times every calibration density. It also uses only the first calibration found for a node at `src/gd_calibration.c:404-410`, while `node_logprior` multiplies all calibrations on that node. Consequently, output from this routine is not a valid prior-only reference for the posterior.

**Fix:** Either sample the exact declared joint time-tree/calibration prior, or run the normal MCMC with the likelihood disabled. Combine all calibration factors and validate the prior sampler against analytic small-tree marginals.

### 4. Critical — modern tips are not modern unless every one is explicitly calibrated

**Location:** `src/gd_calibration.c:198-202`; all nonfixed ages enter the sampler at `src/gd_mcmc.c:426-433`.

**Failure scenario:** A tip omitted from `calibrations.tsv` is a free ancient tip on `[0,1e15]`. A header-only calibration file allows all contemporary languages to drift to absurd ages. For an Arawan user who reasonably assumes present-day taxa default to age zero, this changes both terminal durations and every internal age without an error.

**Fix:** Add explicit sampling-time metadata and require a date/status for every tip. Default only taxa explicitly marked extant to age zero; otherwise fail with a list of undated tips. Distinguish intentional fossil/ancient-tip inference from missing input.

### 5. Major — calibration support and hard/soft semantics are incorrect or unused

**Location:** `src/gd_calibration.c:219-232,274-300,342-359`; `src/gd_analysis.c:309-318,584-589`; schema claim at `docs/input-formats.md:79-87`.

**Failure scenario:**

- `is_hard` is parsed and copied but never affects propagation or density.
- Normal, lognormal, and offset-lognormal calibrations share one proposal-bound formula, `offset + exp(mean + 5*sd)`. For `Normal(1000,100)` this is dimensionally wrong and overflows instead of giving a bound near 1500.
- Proper lognormal tails are silently hard-truncated at five log standard deviations.
- The feasibility check permits parent/child equality in cases where the model documentation requires a positive-duration edge.
- Minimum-only and maximum-only factors are penalties/indicators, not proper age distributions without a base time-tree prior.

**Fix:** Separate mathematical support from proposal initialization. Use distribution-specific support and robust transformed proposals rather than hidden truncation. Either implement `is_hard` or remove it from the schema and document type-defined semantics. Enforce a configurable minimum positive duration on ordinary edges and model intentional zero-length resolutions explicitly.

### 6. Major — offset-lognormal “widen” sensitivity changes the location, not the uncertainty

**Location:** `src/gd_analysis.c:229-244`; parameter definition at `docs/calibrations.md:17-27`; current test covers only Uniform at `tests/regression/test_analysis.c:631-660`.

**Failure scenario:** An offset lognormal uses `(p1=offset, p2=log_mean, p3=log_sd)`, but `widen_window` multiplies `p2`. A factor-of-two sensitivity therefore shifts the median by an exponential amount instead of widening the distribution.

**Fix:** Widen `p3` while holding offset and log-location fixed. Add tests for every calibration family that assert unchanged location/median and increased dispersion.

### 7. Critical — uncalibrated absolute time uses a silent Swadesh-like clock, not validated external rate information

**Location:** tree defaults at `src/gd_analysis.c:360-370` and `src/gd_options.c:58-63`; pair defaults at `src/gd_analysis.c:856-864`; missing empirical sources at `docs/priors.md:19-33,120-124`.

**Failure scenario:** The default tree log-rate mean is -8.80 per year, approximately 0.86 retention per millennium. Pairwise analysis gives every concept the same configured prior at `src/gd_analysis.c:915-924`. No C/CLI path loads `concept_priors.tsv`, `family_priors.tsv`, reference mode, evidence grades, or package version. The empirical Pagel, Vejdemo–Hörberg, and ASJP inputs are explicitly missing; the committed generated package is synthetic scaffolding. An uncalibrated Arawan age would therefore be a classical-clock extrapolation presented with Bayesian precision, not a clock validated out of family.

**Fix:** Remove the silent calendar default. Require an explicitly named, versioned clock package, with its training families, exclusions, units, hyperparameter uncertainty, and leave-family-out performance recorded. Until a defensible package exists, infer and report lexical branch lengths only. Production tooling must refuse synthetic sources or watermark them unmistakably (`tools/reference_builder/synthetic_sources.py:1-16,55-66`; `tools/reference_builder/emitter.py:73-113`).

### 8. Critical — the executable tree model is homogeneous-rate despite documentation and its own negative validation example

**Location:** `src/gd_analysis.c:595-603,659-675`; defaults at `src/gd_mcmc.c:140-142`; negative PPC at `tests/simulation/test_posterior_predictive.c:194-219`.

**Failure scenario:** `date-tree` enables a global rate and optionally branch multipliers, but never `sample_concept_rates`. The test suite deliberately demonstrates that this single-rate model fails data with concept-rate heterogeneity. Stable and rapidly replacing concepts in a small family are nevertheless forced through this exact misspecified model, encouraging the clock and ages to absorb the mismatch and understating uncertainty.

**Fix:** Wire hierarchical concept rates into the public analysis and CLI, loaded by canonical concept ID from external priors with partial pooling and hyperparameter uncertainty. Output their posteriors and information gain. Keep the global-rate version as an explicitly labelled baseline.

### 9. Major — P1 is not the hierarchical robust model described by the model card

**Location:** `src/gd_pairwise_p1.c:166-177`; `src/gd_analysis.c:915-943`; claims at `docs/model-cards.md:52-64`.

**Failure scenario:** `gd_p1_posterior` explicitly ignores `eps_a` and `eps_b`; high-level P1 fixes epsilon to zero, hard-codes family `beta_sd=0.3`, uses standard sensitivity, and supplies the same log-rate prior for every concept. It never loads concept/family priors, confidence, synonym candidates, or loan information. Users may believe Beta contamination and the stated hierarchy were integrated when they were not.

**Fix:** Either rename and document the actual fixed-epsilon lognormal-mixture calculation, or implement the full hierarchy and integrate/sample epsilon and hyperparameters. Add parameter-by-parameter SBC for beta, epsilon, and concept rates.

### 10. Critical — T2 is not an end-to-end inference model, and its advertised meaning weighting is a no-op

**Location:** one-rate sampler state at `src/gd_mcmc.c:154-164`; T2 requires two rates at `src/gd_model_binary.c:440-450`; dataset sum at `src/gd_model_binary.c:307-368`; unused weighting helper at `src/gd_model_binary.c:280-305`; test codifying raw sum at `tests/likelihood/test_t2_likelihood.c:508-528`.

**Failure scenario:** The generic sampler always exposes one rate; the T2 adapter rejects fewer than two. The CLI always constructs T1. Even at likelihood level, `opt->weight` is never used: all cognate-class log likelihoods are summed, so a meaning with $k$ classes contributes $k$ times. This directly contradicts the claimed default that each meaning counts once.

**Fix:** Generalize MCMC to typed rate vectors, with separate gain/loss priors or a rate-plus-equilibrium parameterization. Add forms-to-binary encoding, `--model t1|t2`, complete output, and T2 SBC. Define whether meaning weighting is a composite/power likelihood; apply class weights consistently or, preferably, implement a joint per-meaning polymorphism model.

### 11. Major — T2 silently changes the model when ascertainment correction is numerically difficult

**Location:** `src/gd_model_binary.c:244-276`.

**Failure scenario:** If `log(1-P(all absent))` is nonfinite, T2 returns the raw, uncorrected likelihood with a warning. This changes the posterior exactly at low gain/short duration, where conditioning is strongest. An observed all-absent class is also flagged but assigned a conditional likelihood even though it lies outside the ascertained sample space.

**Fix:** Compute the observable mass with scaled pruning or stable asymptotics; if it cannot be represented, return an error or `-inf`, never the uncorrected target. Reject or explicitly skip all-absent input under ascertainment. Test extreme rates and durations against high-precision calculations.

### 12. Critical — documented cognacy, synonym, loan, status, and alternative-analysis information is discarded

**Location:** `src/gd_forms.c:85-103,124-139,243-258`; tree replay at `src/gd_analysis.c:522-546`; documented contract at `docs/input-formats.md:54-75` and `docs/model-spec.md:439-501`.

**Failure scenario:** The parser recognizes only language, concept, cognate, and primary weight. It ignores `analysis_id`, `cognacy_confidence`, `inheritance_probability`, `loan_probability`, and `status`; picks the single highest-weight form; does not normalize weights; and lets row order break ties. A `status=missing` row becomes an observed cognate, a 0.51/0.49 synonym choice becomes certain, alternative expert analyses can be mixed, and a compatible within-clade loan looks like inheritance and biases the clade young.

**Fix:** Parse and validate the complete schema, require explicit analysis selection, retain all candidates, exactly marginalize pairwise combinations, and marginalize/sample T1 primary states. Implement loan exclusion/mixture/sensitivity at cell or edge level. Preserve missing/excluded/absent distinctions and propagate cognacy-coding uncertainty.

### 13. Major — weight and required-field validation permits malformed data to become scientific observations

**Location:** `src/gd_tsv.c:177-202`; `src/gd_forms.c:110-156,237-250`.

**Failure scenario:** `NaN`, infinity, and negative weights pass `strtod`; NaN makes comparisons false in ways that can select later rows, infinity wins forever, and weights below -1 can make a cell disappear. Short rows become empty language/concept/cognate IDs and are interned as genuine values. Unreadable weights default individually to 1 rather than producing the documented `1/n_candidates` distribution.

**Fix:** Reject nonfinite or out-of-range probabilities, validate within-cell sums, and fail on missing/empty/`.` required identifiers with line/column diagnostics. Add tests for NaN, infinity, negatives, short rows, and duplicate/unnormalized candidates.

### 14. Major — contamination is fixed, whole-concept noise rather than a borrowing model, and promised diagnostics are absent

**Location:** `src/gd_analysis.c:598-602,665-669`; CRP noise at `src/gd_model_novel_state.c:517-531,615-669`; output at `cli/commands.c:434-500`; claim at `docs/model-spec.md:506-544`.

**Failure scenario:** The CLI fixes epsilon (default 0.05), does not sample its Beta prior, and does not output posterior concept responsibilities. One local loan either remains compatible and biases the chronology or sends the entire concept to an exchangeable partition component, discarding its vertical information. The injection test uses deliberately incompatible patterns, not realistic compatible borrowing.

**Fix:** Sample epsilon and report uncertainty and per-concept mixture responsibilities. Add local cell/edge error and borrowing mixtures, with simulations covering compatible and incompatible loans, donor/recipient structure, and clustered contact.

### 15. Major — uncertain-cognacy semantics are internally ambiguous

**Location:** `src/gd_pairwise.c:38-54`; `src/gd_pairwise_p1.c:115-160`; definition at `docs/model-spec.md:161-168,582-589`.

**Failure scenario:** The API takes both a hard `match` and (y_c). Code treats (y_c) as confidence that the hard observation is correct: it first selects the probability of the hard observation, then mixes that with its complement. Documentation calls (y_c) the observed probability of cognacy and gives (y_cp_{match}+(1-y_c)(1-p_{match})), for which a separate hard match is unnecessary. For a hard mismatch with (y_c=0.9), these interpretations reverse the evidence.

**Fix:** Choose one semantics. Either rename the field to observation-correctness confidence and document dependence on `match`, or use (y_c=P(match)) directly. Validate ([0,1]) and add truth-table tests for match/mismatch at (y=0,0.5,1).

### 16. Major — pairwise calendar units and the `absolute_anchored` flag are misleading

**Location:** `src/gd_pairwise.c:209-212`; `src/gd_pairwise_p1.c:210-214,321-330`; defaults at `src/gd_analysis.c:856-864`; BP fields at `src/gd_report.c:438-443`.

**Failure scenario:** P0/P1 mark a result anchored only when a tip age is nonzero. A rate prior expressed per year/per kyr is itself the source of calendar scale, yet contemporary analyses return `*_bp` fields while `absolute_anchored=0`. Conversely, an ancient tip does not by itself validate a transferable rate. The time prior is Uniform over user bounds (default 100–8000 years); saturation or weak data can make those arbitrary bounds determine the result without a bound-mass warning.

**Fix:** Report `calendar_scale_source={none,rate_prior,tip_or_node,both}`, plus whether scale is data-identified or prior-transferred. If no physical-rate source exists, output dimensionless lexical time. Always report posterior mass near both time bounds and run bound/rate-prior sensitivity.

### 17. Major — diagnostics are incomplete and R-hat is not the modern robust statistic claimed

**Location:** `src/gd_diagnostics.c:168-178,182-277`; report at `src/gd_report.c:333-384`; promises at `docs/inference.md:240-253`.

**Failure scenario:** `gd_rhat_rank` computes rank-normalized split R-hat but not the folded rank-normalized scale diagnostic; chains with the same center and different scales can look converged. There is no tail ESS or MCSE. The Geyer pairing begins with `rho[1]+rho[2]` rather than the standard paired sequence beginning at `rho[0]+rho[1]`, so ESS truncation can differ from Stan/ArviZ. Inputs are not prescanned for NaN and count products are unchecked.

**Fix:** Port and golden-test the current Stan/Vehtari definitions: maximum of rank and folded R-hat, bulk and tail ESS, and MCSE. Compare fixed vectors against Stan/ArviZ, including scale-only mismatch, heavy tails, stuck tails, and NaNs. Emit hard warnings/failures under a publication mode.

### 18. Major — output is insufficient to audit the claimed posterior

**Location:** `cli/commands.c:434-500`; result contract at `include/gd_analysis.h:181-211`; promised files at `docs/inference.md:226-268`.

**Failure scenario:** `date-tree` writes only `posterior_nodes.tsv`, `diagnostics.tsv`, and a manifest. It omits posterior rates/hyperparameters/concepts, pointwise log likelihood, samples, per-concept contamination, calibration conflict, root-clock correlation, bound mass, prior/posterior information gain, and a tree absolute-scale flag. Fixed nodes are absent from node summaries. Users cannot reproduce derived summaries, conduct PSIS-LOO, or see that a date is prior- or bound-determined.

**Fix:** Emit a stable posterior-draw format and every documented summary, including all nodes. Record every model option and prior-package identity. Store pointwise likelihood and per-concept responsibilities. Make identifiability and convergence warnings machine-readable.

### 19. Critical — topology is mandatory and its uncertainty is ignored

**Location:** `src/gd_analysis.c:463-471`; `PLAN.md:31-35`; `docs/scientific-methods.md:31-33`.

**Failure scenario:** With cognate data but no tree, Clepsydra cannot run. With a tree estimated from the same cognates elsewhere, it conditions on the selected topology and reports node-age intervals that exclude topological selection uncertainty. This directly misses the owner's “whether or not a tree is given” goal.

**Fix:** Implement topology inference with a rooted topology prior and validated NNI/SPR moves, or first accept a posterior sample/set of trees and average chronology over it. Summarize clade support and node ages conditional on clade presence. Until then, require multi-topology sensitivity and label all ages conditional on the supplied tree.

### 20. Major — zero or silently skipped data can produce successful prior-only-looking dates

**Location:** pair intake at `src/gd_analysis.c:904-945`; decay validation at `src/gd_decay.c:97-107`; tree row mapping at `src/gd_analysis.c:494-503`.

**Failure scenario:** Unknown pair language IDs become `SIZE_MAX`; under a decay model this leads to zero concepts and a flat likelihood, yet the command succeeds and reports the time prior as a BP posterior. Tree dating likewise has no requirement that any forms row match a tip; all lexical rows may be skipped and the run can still return a chronology.

**Fix:** Reject unknown language IDs, zero shared concepts, and preferably analyses below a prespecified overlap threshold. Require at least one informative matched tip/concept in tree runs, report data coverage by language/concept, and fail on excessive skipped data.

### 21. Major — language IDs may resolve to internal nodes, corrupting the observation model

**Location:** `src/gd_analysis.c:500-503,526-545`.

**Failure scenario:** Forms languages are resolved by global tree label lookup without checking `is_leaf`. If a language ID equals a labelled clade, its lexical state is inserted as an internal-node observation. This can radically alter the pruning likelihood while appearing to be an ordinary matched language.

**Fix:** Use a leaf-only map and reject labels resolving to internal nodes. Separately support ancestral observations only through an explicit schema and validation path.

### 22. Major — polytomies are accepted but the number of languages is computed with a binary-tree formula

**Location:** `src/gd_analysis.c:423-426,748-751`.

**Failure scenario:** `(nnodes+1)/2` is valid only for full rooted binary trees. A four-tip root polytomy has five nodes and is reported as three languages, corrupting manifests and downstream interpretation.

**Fix:** Count nodes with `is_leaf`. Add binary, multifurcating, unary-invalid, and single-tip tests.

### 23. Major — calibration initialization can silently force an invalid boundary state, and MCMC defeats the feasibility guard

**Location:** `src/gd_calibration.c:397-453`; `src/gd_mcmc.c:380-381`.

**Failure scenario:** If rejection sampling fails after 1000 attempts, initialization assigns `age=lo` and succeeds; if `lo>hi`, it also assigns `lo`. That can put a node on an order equality or a lognormal boundary with `-inf` density. Separately, the chain constructor changes `cal->feasible` to true instead of rejecting an infeasible calibration set.

**Fix:** Never mutate feasibility. Return `GD_E_CALIBRATION` for unresolved/infeasible inputs. Use robust truncated samplers/inverse CDFs and verify finite initial likelihood and prior before starting the chain.

### 24. Major — MCMC configuration, arithmetic, and error propagation are not robust enough for a public scientific API

**Location:** `src/gd_mcmc.c:293-318,466-470,515-516,569,634,686,713-717,864`.

**Failure scenario:** Many means, steps, initial values, epsilon parameters, and iteration products lack finite/range checks. `n_samples*thin+n_warmup` can overflow. A zero or NaN proposal step can freeze/poison a chain. Likelihood callback errors are converted to `GD_E_INTERNAL`, hiding the true cause.

**Fix:** Create one comprehensive public configuration validator, use checked multiply/add for iteration and storage sizes, require finite initial target density, and propagate exact callback error codes. Assert that the requested number of draws was actually stored.

### 25. Major — checkpoint files neither bind to the target analysis nor resume retained sampling correctly

**Location:** `src/gd_mcmc.c:776-866`; limited test at `tests/simulation/test_mcmc_tree.c:372-428`.

**Failure scenario:** The checkpoint verifies only magic/version/parameter count/checksum; it does not hash topology, data, calibrations, model/config, or typed parameter mapping. Another analysis with the same parameter count can accept and mis-map it. It omits retained samples, `n_stored`, pointwise data, and some proposal counters, so a mid-sampling restore cannot reproduce an uninterrupted run. Tests checkpoint only during warm-up.

**Fix:** Bind checkpoints to canonical hashes of all target inputs and typed parameter metadata. Serialize phase, target iteration, retained draws or an append-safe output position, and all adaptation/proposal state using a portable byte format. Test warm-up and mid-sampling resume plus deliberate cross-analysis rejection.

### 26. Major — several numerical failure paths silently change the target or return success

**Location:** `src/gd_pairwise.c:19-60,196-207`; `src/gd_pairwise_p1.c:115-187,314-334`; `src/gd_decay.c:33-64,121-126`; `src/gd_model_binary.c:76-99`; `src/gd_model_novel_state.c:438-459,585-605,791-799`; `src/gd_grid.c:64-187`.

**Failure scenario:** Public pair functions do not consistently reject nonfinite rates/probabilities; density allocation failure can still return success; invalid decay parameters become similarity 0.5; T2 rate-sum overflow can produce an identity transition instead of the high-rate stationary limit; relaxed multipliers can overflow; grid summaries accept invalid density. The reported “HPD” is the min/max span of selected high-density cells, which bridges low-density gaps in multimodal posteriors and is not a shortest contiguous interval.

**Fix:** Centralize finite/domain validation, make required allocations fatal, keep calculations in stable log/scaled form, map invalid MCMC proposals to `-inf` without aborting the chain, and reject invalid grids. Implement a contiguous minimum-width credible interval or label/output a genuine possibly-disconnected highest-density set.

### 27. Major — the CLI parser and file reader silently accept incomplete requests/input

**Location:** `cli/commands.c:165-179,228-231,318-332`.

**Failure scenario:** A recognized final option with no argument is skipped and its default used; `--rate-logsd` at the end of an otherwise valid command succeeds. File loading does not verify that `fread` returned the measured length or check `ferror`, so a truncated prefix can be hashed and analyzed as the full input.

**Fix:** Use one strict option parser that requires values, rejects duplicates where appropriate, and reports the exact option. Check complete reads and I/O errors, or stream into a checked growable buffer. Add option-at-end and short-read tests.

### 28. Major — public C API edge cases include a null-pointer crash and undefined RNG arithmetic

**Location:** `src/gd_newick.c:139-146,425`; `src/gd_rng.c:58-69,126-170`.

**Failure scenario:** `gd_newick_parse` does not validate its `out` pointer and unconditionally writes through it. Bounded RNG with zero divides by zero; bound `0x80000000` enters signed-overflow undefined behavior. Extreme-shape Beta sampling can underflow both gamma draws and insert an artificial point mass at 0.5.

**Fix:** Validate/output-null all public ownership pointers. Implement unsigned threshold arithmetic (`-range % range`) with explicit zero handling. Use a log-domain or specialized extreme-shape Beta algorithm and add boundary tests. These are API robustness defects even where current CLI paths do not trigger them.

### 29. Major — the validation suite does not test the regimes needed to trust published dates

**Location:** tree SBC at `tests/simulation/test_mcmc_tree.c:89-214`; PPC at `tests/simulation/test_posterior_predictive.c:168-219`; plan at `docs/validation.md:138-210`.

**Failure scenario:** Tree SBC fixes the root, uses one strict-clock quartet, and pools log-rate and two node-age ranks into one histogram, allowing opposite biases to cancel. Block scaling is off in that SBC, so it cannot validate its Jacobian. Relaxed/contamination tests are recovery trends rather than SBC. The PPC evidence is one seeded well-specified dataset and one extreme 0.15x/6x mixture with fixed ages. There is no SBC for an uncalibrated root, CLI hierarchy, T2 MCMC, synonyms, alternative codings, or realistic missingness/loans.

**Fix:** Run parameter-class-specific rank ECDFs and interval coverage for every executable configuration, with all proposal blocks enabled. Factor over tree sizes/shapes, calibration count/placement, free roots, concept and branch variation, contamination, synonymy, missingness, and coding error. Use an independent simulator/oracle where possible and repeated PPC power/type-I-error experiments.

### 30. Major — the real-data calibration benchmark overstates independence and leaks information into support

**Location:** `docs/validation.md:298-335`; `examples/loco_benchmark/README.md:50-96`; `tools/validation/calibration_benchmark.py:83-110,166-200`.

**Failure scenario:** Nine held-out tips are presented across three “independent” families, but Romance is nested within Indo-European and Latin is held out twice from the same IE-CoR source. The uniform upper support is computed using all calibration rows, including the row later held out, so the answer influences its own support. Results count toward coverage even with low ESS or failed convergence. Relaxed intervals are often thousands of years wide; 8/9 coverage alone does not show useful precision.

**Fix:** Predeclare support and priors independently of every held-out datum. Deduplicate sources, cluster uncertainty by family, enforce convergence/MCSE gates, and use interval score, CRPS/log score, sharpness, and coverage. Expand to genuinely independent families and held-out internal-node calibrations.

### 31. Major — current scientific assumptions remain inadequate for the ultimate goal even after implementation bugs are fixed

**Location:** acknowledged assumptions at `docs/model-spec.md:189-212,415-417,439-501,781-809`.

**Failure scenario:** Constant-rate memoryless replacement extrapolates shallow historical rates into deep time; branch multipliers do not model time-dependent rates or split pulses. Meanings are treated as independent despite semantic/domain and coding correlations. Missingness is ignorable. T1 assumes one primary state and strict vertical inheritance; whole-concept contamination is not a contact network. For six to eight Arawan languages with no written record, these misspecifications and the unknown absolute clock dominate nominal MCMC error.

**Fix:** Add and validate local/epoch clocks and split-pulse sensitivity; model or cluster concept-domain dependence; preserve missingness mechanisms; propagate coder/analysis uncertainty; and add explicit borrowing/transfer models or realistic sensitivity simulations. The uncertainty statement must include model, topology, coding, rate-transfer, and calibration uncertainty, not only conditional MCMC variance.

## Bottom line for Arawan

With six to eight languages, no written records, and no historical calibration, cognate data can inform relative branch lengths and some relative node ordering. It cannot create an absolute calendar scale. Clepsydra's current BP output would obtain that scale from a silent, unvalidated rate prior while its node-age measure and hidden upper bound further distort the result. The scientifically defensible near-term product is therefore: infer lexical-time branch lengths over multiple plausible trees/codings; show borrowing and missingness sensitivity; then, if desired, transform those results under several explicit external clock priors whose provenance and out-of-family calibration are displayed. A single “well-calibrated posterior age for each node” is not currently available from these data or this implementation.
